# Design Critique

A format that gets to useful feedback in 5–7 minutes.

## Flow

### 1. Read the intent
State in one sentence what the design is trying to do. Confirm with the user.

### 2. What works
Name 2–3 things that are landing. Specific beats generic ("the primary CTA is unambiguous" beats "looks good").

### 3. Friction points
For each:
- Where the user has to think harder than they should.
- Where the design contradicts the user's mental model.
- Where information is missing, hidden, or wrong.

For each point: **one** concrete fix. Not a list — a single change.

### 4. Open questions
- What's the smallest test that would de-risk the biggest assumption?
- Who is the design for, and who is it accidentally for?

## What to avoid
- "Maybe we could…" — pick one direction.
- Solving problems the user didn't ask about.
- Bikeshedding color when the information architecture is broken.
